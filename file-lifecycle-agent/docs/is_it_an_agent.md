## 결과: 대회 공지 캡처 재시험

`_project.md`를 넣고 같은 대회 공지 캡처를 다시 돌렸더니, 이번에는 **KCC 에이전트로 바로 지정**했습니다.
처음에는 "KCC 에이전트인가요, 비전인가요?" 하고 물었던 캡처입니다.

## 에이전트라고 할 수 있나?

**네, 툴 콜링이 실제로 있습니다.** 이번 실행에서 Qwen이 직접 고른 도구 호출 순서입니다.

| # | Qwen이 고른 도구 | 결과 |
|---|---|---|
| 1 | `inspect_file()` | 이미지 → OCR로 글자 읽기로 결정 |
| 2 | `read_content(offset=0)` | 공지 텍스트 읽음 |
| 3 | `search_projects("KCC AI Agent 미니 캡스톤 대회 안내")` | 검색어를 직접 만들어 검색 → KCC 에이전트 1순위 (0.656) |
| 4 | `assign_project("KCC_AGENT", evidence="KCC AI Agent 미니 캡스톤 대회 안내")` | 근거 문장을 원문에서 그대로 인용 |
| 5 | `check_references()` | 다른 곳에서 쓰는 파일인지 확인 |
| 6 | `preview_plan()` → `finish()` | "KCC Agent 폴더로 저장" 계획 |

- **고르는 주체가 모델입니다.** 매 단계 모델이 JSON으로 "어떤 도구를, 어떤 인자로" 부를지 정합니다. 호스트는 그걸 실행해서 결과를 다시 모델에 돌려줍니다(관찰 → 행동 반복).
- **실패하면 고칩니다.** 첫 실행 때 오류가 1번 났는데, 호스트가 오류를 돌려주자 모델이 다음 호출에서 고쳤습니다.
- **멈출지 물을지도 스스로 정합니다.** 확신이 없으면 `ask_user`로 후보를 주며 묻고, 확신하면 지정합니다. 첫 실행에서는 물었고, 이번에는 지정했습니다.
- 이 툴 콜링 능력 자체를 SFT로 학습시켰고, 따로 평가하고 있습니다(`tool_eval.py`).

## 에이전트답지 않다고 느낄 수 있는 부분

1. **규칙이 먼저 실행됩니다.**
   - 쉬운 파일은 규칙 컨트롤러가 같은 도구들을 정해진 순서로 불러 끝냅니다. 이 경우는 사실상 스크립트입니다.
   - 모델은 규칙이 확정하지 못할 때만 개입합니다. 예를 들어 생산운영관리 테스트 파일은 규칙이 끝냈고, 대회 공지는 모델이 처리했습니다.
   - 실제 사용에서 얼마나 자주 모델로 넘어가는지는 웹 화면의 `decider` 값으로 볼 수 있습니다.
2. **도구가 "판단용"뿐입니다.**
   - 이동, 삭제, 셸 실행 도구는 일부러 뺐습니다.
   - 파일을 옮기는 건 모델이 아니라 사람이 승인 버튼으로 합니다.
   - 그래서 행동하는 에이전트라기보다 **판단하고 계획까지 세우는 에이전트**입니다.
3. **흐름이 거의 정해져 있습니다.**
   - 대부분 6단계 비슷한 경로로 끝납니다.
   - 분기는 질문할지 지정할지, 모델 파일이면 관련 파일을 찾을지 정도뿐입니다.

## 전체 파이프라인

```
아이폰 캡처 / 다운로드 / 맥 캡처
  → 감시 (Downloads·Desktop·iCloud KCC-inbox)   ← 트리거, 에이전트 아님
  → 규칙 컨트롤러가 먼저 시도  ── 확정 → 계획
  → 실패하면 Qwen 1.7B 에이전트 루프 (툴 콜링, 최대 N단계)
        inspect → read → search(bge-m3 + _project.md) → assign | ask_user
  → 맥 알림 → 사람이 승인 → 폴더로 저장 (되돌리기 가능)
```

## 대회 발표용 한 줄 설명

> 툴 콜링으로 판단하는 에이전트에 안전장치를 둘러싼 것이다. 쉬운 건 규칙으로 빠르게 끝내고, 어려운 건 모델이 도구를 써서 판단하고, 실행은 사람이 승인한다.

## 더 에이전트답게 만들려면 (아직 구현 안 함)

- 승인 후 `_project.md`를 업데이트하는 도구를 모델이 직접 부르게 하기
- 같은 이름의 파일이 있을 때 모델이 새 이름을 제안하게 하기
